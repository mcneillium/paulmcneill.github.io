### Overview
My first hands-on language-model project, from 2023 to 2024: take GPT-2, fine-tune it on conversation data so it answers in a dialogue style, and put it behind interfaces people can actually use.

---

### What I built
- **Fine-tuning:** GPT-2 (124M parameters) trained with Hugging Face Transformers and the `Trainer` API on the public ConvAI2 dialogue dataset combined with custom domain dialogues (support-style questions and answers). Causal language modelling, sequences of 128 tokens, 3 epochs, batch size 4, on a local NVIDIA GPU. The run (above, August 2024) took 2,622 steps; training loss fell from 2.96 to 2.42 over the first 1.7 epochs.
- **Serving:** a Flask API (`/api/generate`) that loads the fine-tuned model and generates replies with nucleus sampling (top-p 0.9, top-k 50, temperature 0.7) and a block on repeated phrases.
- **Three interfaces on the same model:** a web page, a Tkinter desktop app and a Streamlit app, plus an early React front end.
- **Optional storage** of the model in AWS S3.

---

### What went wrong, and what changed
- The ConvAI2 and custom data had different structures; merging them took a preprocessing step for each.
- Early runs overfitted, which I corrected by adjusting the learning rate and the number of epochs.

---

### What I would do differently now
I judged the replies by reading them. Today I would hold out a set of dialogues and report perplexity on it, compare against the untuned GPT-2, and keep the training data with the code so the run can be repeated. Those habits are what my later work is built on: see the [research studies](/research/), which fix the protocol before any model is fitted.

### Tech stack
Python, PyTorch, Hugging Face Transformers and Datasets, Flask, Tkinter, Streamlit, React, AWS S3 (optional).
